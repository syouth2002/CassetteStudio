# Dolby B・C相当機能の実装調査

調査日: 2026-10-26。対象: Cassette Studio 0.1.1。

## 結論

Rustによるソフトウェア処理として開発する技術的な見通しはある。ただし「高域を強調する機能」と「既存のDolby B/Cデッキで正しく復号できる機能」は別の達成条件である。後者には周波数・入力レベル・過渡応答・基準レベルの一致が必要になる。

公開一次資料から方式、回路構成、いくつかの具体的な特性値は確認できた。一方、公式の完全な適合仕様、すべての検出器定数、公式試験一式は取得できていない。現段階で完全互換や認証取得を表明する根拠はない。本資料は実装設計と検証の出発点であり、完成した互換仕様書ではない。

以下では、出典を付けた事実と、本アプリ向けの設計提案を区別する。今回の作業ではアプリの音声処理は変更していない。

## 1. 方式の概要

録音前のエンコードと、テープ再生時の相補的なデコードを組み合わせる方式である。テープで加わったヒスノイズは、再生側の処理によって抑えられる。通常の音楽ファイルだけに処理をかけても、元ファイルのノイズを除去する用途にはならない。

| 項目 | B型 | C型 |
|---|---|---|
| 低レベル時の効果の目安 | 約4kHz以上で最大約10dB | 約2〜10kHzで最大約20dB |
| 低レベル特性の広がり | 約300Hz付近から影響が現れる | 約100Hz付近から影響、400Hz付近で約15dB |
| 基本構成 | スライディングバンド1段 | 動作レベルをずらした2段 |
| 追加機構 | レベル検出・過渡保護 | スペクトルスキュー、アンチサチュレーションも必要 |

これは概説上の目安であり、300Hzや100Hzを固定ハイパスフィルターの遮断周波数として設定するという意味ではない。信号の強さとスペクトルによって動作帯域が変わる。[Dolby Laboratories, Bulletin 212](https://manuals.sterremuur.nl/Tapedecks/212_Dolby_B,_C_and_S_Noise_Reduction_Systems.pdf)

Ray DolbyのC型発表論文の抄録も、圧縮器2段と伸長器2段、最大圧縮比を大きく増やさずに低減量を増す構成、過渡応答とテープ飽和への対策を説明している。今回確認したのは抄録と書誌情報で、論文PDF本文の取得には成功していない。[AES Convention 70, Paper 1850, 1981](https://aes.org/publications/elibrary-page/?id=11906)

## 2. 処理として必要なもの

### 2.1 B型

通常の固定EQや全帯域コンプレッサーでは再現できない。直通経路と、フィルター・レベル検出・過渡抑制を備える補助経路を組み合わせる。小さい信号と大きい信号ではほぼ一定の利得になり、その中間のレベル範囲で利得が変化する。

デジタル実装では、可変フィルター、検出器の状態、補助経路の制限特性をサンプル列全体にわたって計算する必要がある。復号側を単に「エンコードの増幅量をマイナスにする」処理にはできない。

デジタルB型復号に関する公開特許には、スライディングバンド、過渡抑制、差分合成、制御用フィルター、非線形積分器による方式が記載されている。アナログの無遅延フィードバックを直接デジタル化する問題に対し、フィードフォワード構成への変換を扱っている。これは実装方式の参考になるが、本アプリが同じ適合性を満たす証拠にはならない。[US20030004591A1、特に段落0015–0025](https://patents.justia.com/patent/20030004591)

### 2.2 C型

公開特許のC型実施例では、2段のフィルターの静止時コーナーを約375Hzとし、後段の動作しきい値を約10〜15dB下げる。復号は低レベル段から高レベル段の順になる。同実施例には、全波整流、B型の半分の平滑時定数、約10kHzのスキュー処理も記載されている。

重要なのは、これらが特許中の具体的実施例である点である。記載された数値だけで全製品共通の適合仕様が完成するわけではない。また、同文献の約425μsなどの値は信号フィルターの時定数であり、検出器のアタック時間と混同しない。[Ray M. Dolby, US4490691、Fig.50の説明](https://www.freepatentsonline.com/4490691.html)

したがって実装には、異なる動作レベルの2段に加えて、高域の制御誤差を抑えるスキュー処理と、テープの高域飽和を抑える処理、その相補復号が必要になる。B型の完成後に、別のC型モードとして検証する。

### 2.3 時間応答

単一のアタック秒数とリリース秒数を設定するだけでは不十分である。検出器の非線形動作と短い突発信号の過渡保護を含めて、時間領域で合わせる必要がある。今回、B/C両型について採用可能と断定できる一組の絶対時間定数は確定していない。

設計上は、信号用フィルター、制御用フィルター、整流、平滑、過渡抑制を個別の状態として持たせる。一般的な一次平滑化の係数 `exp(-1 / (sample_rate * time_constant))` は離散化の道具にはなるが、これ自体がDolbyの検出器仕様ではない。

## 3. 照合に使える具体値

SonyのCXA1330/1331/1332データシートには、B/Cのエンコード増幅量が記載されている。以下は同資料p.6の代表値で、正式な全方式共通の許容差ではない。入力レベルは同資料のDolby基準に対する相対値である。

| モード | 周波数 | 入力レベル | 増幅量の代表値 |
|---|---:|---:|---:|
| B | 500Hz | −25dB | +2.9dB |
| B | 5kHz | −25dB | +5.4dB |
| B | 10kHz | −40dB | +10.4dB |
| B | 10kHz | 0dB | +0.4dB |
| C | 500Hz | −60dB | +16.2dB |
| C | 2kHz | −60dB | +20.7dB |
| C | 2kHz | −25dB | +7.4dB |
| C | 10kHz | 0dB | −3.5dB |

同資料p.14の基準電圧は、NR OFF時のREC OUTで388mVrms。端子・機種を指定して解釈する必要がある。[Sony CXA1330シリーズ、pp.6,14](https://www.elektronikjk.com/elementy_czynne/IC/CXA1330M.pdf)

別のB型ICであるNE645/646は、Pin 3の580mVrmsを0dBとする。したがって388mVや580mVを、すべてのデッキの外部入力端子に共通する基準と扱ってはいけない。[Signetics NE645/646、電気特性表](https://www.electrokit.com/upload/product/11077/110779/NE645B.pdf)

## 4. アプリに必要な校正機能（設計提案）

既存の−18LUFSへの音量合わせは、曲の聴感音量を揃える機能である。NRの基準レベル校正は、デジタル振幅と、音声出力・デッキ・テープ上のレベルとの対応を合わせる機能として別に扱う。

内部では、校正したデジタルRMS振幅を `A_ref` として、検出器に渡す相対レベルを次のように定義できる。

`relative_db = 20 * log10(signal_rms / A_ref)`

これは校正値を表すための設計式である。NRの制御を単純な全帯域RMSだけで行うという意味ではない。正弦波のピークとRMSも区別する。

校正プロファイルには、出力機器、左右チャンネルの基準、OS・アプリの出力音量、デッキの入力設定、サンプルレート、校正日を保存する。物理デッキでの設定には対象機のサービス資料と、適切な基準テープまたは基準機器が必要になる。今回、特定デッキの磁束基準と校正手順までは確定していない。

録音先デッキにB/Cエンコーダーがある場合は、次の経路を明確に区別する。

- アプリでエンコードする場合: デッキ側の録音NRはOFF、再生時は対応するB/Cを使用する。
- デッキでエンコードする場合: アプリ側NRはOFFにして、デッキの録音NRを使用する。

二重エンコードを避けるため、UIにも録音経路を表示する。エンコード済みWAVにはモードと校正プロファイルの識別情報を添える。

## 5. Cassette Studioへの組み込み案

以下は調査時点の `src/audio.rs` を確認した上での設計提案である。現在は `src/audio/` 配下へ役割別に分割している。現在の構成は[ソース構成ガイド](architecture.ja.md)を参照。

```text
音源のデコード・チャンネル変換
  → 無音部分の除外・DC除去・曲ごとの音量調整
  → A/B面の曲配置・途中開始・フェード・曲間無音
  → 面全体を連続した浮動小数点PCMとして処理
  → 校正済みのB/C相当エンコード
  → 必要な最終量子化・ディザー
  → 録音用再生 / WAV保存
```

現状は曲断片を16bit PCMへ変換して順に書き込んでいる。新処理では、最終量子化の前にNRを置き、面全体で状態を保持できる構成へ変更する。

### 実装上の要点

- Rustの音声処理モジュールを独立させ、B/C、エンコード/デコード、校正、フィルター状態を持たせる。
- 左右は独立した状態から実装を始め、互換性に影響する共通検出を無断で追加しない。
- 曲境界や無音区間でも処理を継続する。曲や処理ブロックごとに検出器をリセットしない。
- A面とB面は別のストリームとして初期化する。A面で切れた曲をB面で再開する場合も、B面の音声順で処理する。
- フェードはエンコード前に適用する。エンコード後のフェードでは、実機のデコーダーが想定と違うレベルを受け取る。
- エンコード後に音量正規化やリミッターをかけない。クリップする場合は、校正値を固定したままエンコード前の録音レベルを下げ、再生成して確認する。
- 再生途中へのシークには、事前生成音声、または状態を再現できるチェックポイントを使う。
- 録音用出力と通常の試聴を区別する。試聴用に復号する場合と、デッキへ送るエンコード信号の場合を明示する。
- 試聴とWAV生成で同じ処理経路を使う。キャッシュキーにはNR方式、処理版、校正、音量、DC、フェード、曲順を含める。

44.1kHzでの高域特性と非線形処理を評価し、必要なら内部オーバーサンプリングを採用する。倍率は測定で決め、規格上の必須条件とは扱わない。量子化前の処理は浮動小数点で行う。

## 6. 検証計画（本プロジェクトの提案）

### 静的特性

基準に対して0/−10/−20/−30/−40/−50/−60dBの試験信号を使い、100/200/400/500Hz、1/2/4/8/10/15/20kHzを測定する。この組み合わせは試験案であり、公式適合試験の指定ではない。

Sonyデータシートの個別試験点と、公開資料の連続した特性曲線を両方照合する。数点だけを通過するように調整して完了としない。

### 動的特性

音量ステップ、短いバースト、打楽器、持続する高域に小さい中域を加えた信号、フェード、曲間無音を使う。ポンピング、過渡の歪み、帯域の戻り方を測る。左右で違う信号も確認する。

### 相互運用

1. ソフトエンコード → ソフトデコード: 数値安定性と自己往復の確認。
2. ソフトエンコード → 実機デコード: 今回の録音機能の主要な合否判定。
3. 実機エンコード → ソフトデコード: 復号側の独立確認。
4. 実テープ往復: テープの周波数特性・飽和・校正誤差を含めた確認。

自己往復が正しくても、両側に同じ間違いがあれば実機互換にはならない。まず電気的な接続で処理自体を確認し、その後テープを含める。可能なら複数メーカーの正常なデッキで比較する。

基準レベルずれや高域減衰も意図的に加え、誤差への挙動を記録する。許容差は実測と資料照合後に決める。今回の調査だけで公式の合格値は定義しない。

## English summary

An independent Rust implementation is technically plausible, but hardware interoperability requires matching level-dependent spectral processing, nonlinear detector dynamics, transient suppression, and calibrated reference levels. Dolby C additionally requires staggered stages, spectral skewing, and anti-saturation processing. Public descriptions, patents, and IC test points do not constitute a complete conformance specification.

For Cassette Studio, process the complete assembled side, including fades and gaps, through a continuous floating-point encoder before final PCM quantization. Keep loudness normalization separate from NR calibration. Validate software-to-hardware interoperability, rather than relying only on a software round trip. Begin with B-type measurement and implementation, then extend the verified foundation to C-type. No application DSP changes were made during this research.
